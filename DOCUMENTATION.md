# Веб-сервис для анализа МРТ-снимков
Анализатор изображений, основанный на свёрточной нейронной сети ResNet

## 1. Обзор решения

**МРТ-анализатор** — веб-сервис, который принимает МРТ-снимок головного мозга,
определяет наличие и тип опухолевого образования и выделяет предполагаемую
область опухоли на изображении.


Решение состоит из двух последовательно работающих моделей:

| Задача | Модель | Выход |
|---|---|---|
| Классификация | Ансамбль ResNet34 (5-fold CrossVal) | 1 класс из 4 + вероятности классов|
| Локализация | U-Net (энкодер ResNet18) | маска области опухоли |

Класс «Опухоли нет» свидетельствует об отсутствии объекта для локализации: при нём
сегментационная модель возвращает пустую маску, не отображающуюся на снимке. Мы планируем исправить ход модели и при определении данного класса исключить обработку снимка сегментационным разделом.

Прогноз модели должен интерпретироваться исключительно как **вспомогательная информация для врача**,
а не медицинское заключение!

## 2. Данные для обучения

### 2.1. Исходный набор данных и их перераспределение

В качестве исходного датасета для классификации было использовано 24 572 МРТ-изображения головного мозга
с контрастным усилением, распределённых по 4 классам:

- глиома;
- менингиома;
- опухоль гипофиза;
- отсутствие опухоли.

Ссылка на датасет: https://disk.yandex.ru/d/SW2W69XsB2yubA

Разделение на тестовые и обучающие данные было произведено в исходном датасете и составило 4 828 на 19 744 снимков соответственно
Из тренировочной вывборки для валидации было отобрано 20% снимков случайным образом (для формирования кросс-валидационной модели)


Для обучения модели сегментации был использован набор из 1 978 снимков 110 различных пациентов, содержащих изображения снимков и масок
Ссылка на датасет: https://www.kaggle.com/datasets/mateuszbuda/lgg-mri-segmentation
В процессе предобработки обучающая выборка была разделена на тренировочную и валидационную в соотношении 1:4
В качестве тестовой выборки были использованы данные из стороннего датасета, что будет исправлено при дальнейшей лоработке модели

### 2.2. Предобработка и устойчивость к качеству изображений

Снимки в наборе данны различались по размеру, яркости, контрасту и обрезке.
Для приведения всех снимков к единому формату тензора PyTorch в блок предобработки были включены следующие функции (`model_def.py`):

1. **Чтение в градациях серого** — Переведение изображение в одноканальный формат
2. **`CropForeground (порог > 10% от max яркости)`** — автоматическая обрезка неинформативной зоны вокруг
   головы: снимки с разной площадью фона приводятся к компактному кадру;
3. **`ScaleIntensityRangePercentiles (1–99 %)`** — нормировка яркости
   по перцентилям конкретного снимка: обеспечивает устойчивость решения к общему уровню
   и контрасту изображения, разным настройкам окна при экспорте DICOM;
4. **`Resize (длинная сторона → 224)` + `SpatialPad (224×224)`** — приведение
   к единому размеру при любом исходном разрешении и соотношении сторон,
   без искажения пропорций. Использовали симметричный паддинг;
5. Приведение к `float32` в диапазоне [0, 1].

Для повышения устойчивости модели к вариациям положения и яркости использовали функции аугментации при обучении: случайный поворот (±0.17 рад), сдвиги/масштаб
(RandAffine), контрастная коррекция (RandAdjustContrast)

Сегментатор (`segmenter.py`) использует ту же схему нормализации и приведения
к 224×224 (порог `CropForeground` 0.04 после нормализации [0, 1]), что
гарантирует согласованность входов обеих моделей.

## 3. Модели обнаружения и локализации 

### 3.1. Классификатор: ансамбль из 5-фолдовой кросс-валидации модели ResNet34

**Архитектура:** ResNet34 с изменениями под задачу:
- ResNet34 — проверенная архитектура компромиссной сложности: достаточно
  ёмкая для рентгенологической картины, при этом быстро реализуемая на CPU
  (~0.5 с на снимок с ансамблем из 5 моделей);
- входной свёрточный слой — 1 канал (градации серого) вместо 3;
- выходной слой — 4 класса.

**стратифицированная кросс-валидация по 5 фолдам** 
- даёт 5 моделей на разных разбиениях данных — и оценку устойчивости обучения к конкретному исходному набору данных;
- на данном этапе разработки один из фолдов проседает в качестве классификации и значительно хуже идентифицирует менингиомы
**ансамбль (усреднение softmax-вероятностей 5 фолд-моделей)** 
сглаживает ошибки отдельных моделей: на интеграционных проверках прототипа ансамбль корректно распознавал все проверенные снимки (менингиома, глиома, «опухоли нет») с уверенностью 98–99.9 %, тогда как отдельные фолды ошибаются заметно чаще (см. раздел 4);

**уверенность модели** 
- сочетание прогностического и вероятностного выходов позволяют оценить пользователю степень уверенности модели в выборе

Веса: `models/best_model_fold_1.pt … fold_5.pt`.

### 3.2. Сегментатор: U-Net

**Архитектура:** U-Net (библиотека `segmentation_models_pytorch`),
- U-net - модель, сконструированная по логике энкодер-декодер со skip-связями, хорошо выделяет локальные паттерны при малом
  числе обучающих примеров; 
  - перенос обучения с ResNet18-энкодером ускоряет сходимость признаков;
- для ускорения обучения использовали предобученные веса ImageNet для энкодера;
- входной свёрточный слой — 1 канал;
- выход — вероятностная маска (функция активации - сигмоид) накладывается на исходный снимок красным полупрозрачным
  слоем (коэффициент смешивания 0.5, порог бинаризации 0.5) — врач видит
  предположительную область непосредственно поверх исходных данных.

**Обучение** (`train_segmentation.ipynb`):
- функция потерь: DiceLoss (прямо оптимизирует целевую метрику),
- оптимизатор: Adam lr = 1e-4, batch 16 (алгоритм с коррекцией смещения, показал лучшее качество обобщения, нежели стохастический градиентный спуск с моментом Нестерова, возможно, будет заменён при доработке)
- Лучший Dice на валидации — **0.795** (epochs 12–17: 0.79–0.80).

**Сравнение архитектур** (один валидационный набор,
метрики Dice / IoU / Precision / Recall / Accuracy):

| Модель | Dice | IoU | Precision | Recall | Accuracy |
|---|---|---|---|---|---|
| **U-Net++** | **0.94** | **0.93** | **0.95** | **0.93** | **0.95** |
| U-Net | 0.86 | 0.82 | 0.90 | 0.88 | 0.91 |
| Attention U-Net | 0.84 | 0.81 | 0.89 | 0.87 | 0.90 |

Лучший результат у U-Net++ (плотные skip-связи точнее передают границы);
блоки внимания прироста не дали.

Веса: `models/segmentation_model.pt`.

### 3.3. Инференс

- Классификация: среднее вероятностей 5 моделей, итоговый класс — аргмаксимум,
  уверенность — вероятность итогового класса;
- Сегментация: маска масштабируется к исходному разрешению снимка
  (ближайшая соседняя интерполяция, без размытия границ) и накладывается
  на исходный снимок;
- вычисления на CPU 
- суммарное время обработки одного снимка — около 1 секунды.

## 4. Оценка качества

### 4.1. Метрики классификатора и локализатора

- Кросс-валидация классификатора в `train_classifier.ipynb`; каждая фолд-модель оценивалась
на отложенной стратифицированной тестовой выборке (222 снимка):

| Фолд | Accuracy | F1-macro | AUC-макро | AUC «опухоль/нет» |
|---|---|---|---|---|
| 1 | 0.833 | 0.832 | 0.946 | 0.988 |
| 2 | 0.788 | 0.779 | 0.935 | 0.991 |
| 3 | 0.811 | 0.811 | 0.954 | 0.993 |
| 4 | 0.779 | 0.773 | 0.942 | 0.992 |
| 5 | 0.694 | 0.609 | 0.921 | 0.991 |

Ключевой для практики показатель — различение «есть опухоль / нет опухоли»:

- чувствительность 0.93–0.94 (пропуск 9–11 опухолей из 162) - основное направление доработки;
- специфичность 0.95–0.97 (ложно положительный результат 2–3 из 60);
- AUC «опухоль/нет» 0.99.

AUC по отдельным классам (лучший фолд): «Опухоли нет» 0.99, «Гипофиз» 0.96,
«Глиома» 0.93, «Менингиома» 0.89.

### 4.2. Метрики классификатора и локализатора

 - Dice loss на валидации — 0.80 (лучшая эпоха 0.795); 
 - сравнение трёх архитектур — см. таблицу в разделе 3.2 (лидер U-Net++: Dice 0.94, IoU 0.93).

### 4.3. Анализ ошибок

По матрицам ошибок фолдов основные области ошибочных определений:

1. **Глиома ↔ менингиома** — главное несоответствие (до 30 % снимков глиомы
   относилось к менингиоме в худшем фолде). Классы объективно похожи
   на 2D-срезках: менингиомы и глиомы могут иметь сходную интенсивность
   и локализацию;
2. **Гипофиз → менингиома** — ошибочное определение 11–28 %: близкая
   анатомическая область;

3. Практически значимое разделение «опухоль/нет опухоли» стабильно высокое во всех фолдах (AUC 0.99) — модель уверенно отвечает на основной вопрос скрининга, а тип опухоли указывает менее уверенно. 

### 4.4. Ограничения решения

1. **2D-анализ по отдельным срезам** Классификация и сегментация работают
   с одним изображением, а не с 3D-исследованием: анализ объёмного образца
   (нарастание/исчезновение маски по срезам) может повысить точность как локализации, так и определения типа опухоли;
2. **Неточность определения класса опухоли** при близких вероятностях классов
   интерфейс показывает низкую уверенность
3. **Сегментация не находит образование на отдельных срезах глиом** —
   при уверенной классификации «глиома» маска на некоторых срезах пуста
   (диффузные границы, слабый контраст)
4. **Зависимость от протокола съёмки:** датасет — Т1 с контрастным
   усилением; на других режимах (Т2, FLAIR) модель не валидировалась.

### 4.5. Пути минимизации критичных ошибок

- отдельный бинарный детектор «опухоль/нет» с повышенным порогом чувствительности, для полного исключения ложно-отрицательных ответов модели
- новая модель ансамблирования
- сегментация: расширение обучающей выборки


## 5. Прототип


### 5.1. Техническая реализация

- **Backend:** Python 3.12, Flask. Маршруты: `GET /` (форма),
  `POST /process` (обработка). Валидация: расширение + реальный формат
  (Pillow) + размер; оригинал пользователя сохраняется под случайным UUID
  и удаляется после обработки.
- **ML:** PyTorch 2.14 (CPU), MONAI (препроцессинг),
  segmentation_models_pytorch (U-Net). Модели загружаются один раз
  при старте (~480 МБ RAM).
- **Frontend:** серверный рендеринг Jinja2,
  (шрифт Mulish), адаптивная вёрстка.
- **Результат обработки** сохраняется в `static/results/<uuid>/`:
  `input.png` (превью), `output.png` (с подсветкой), `data.csv`.

Формат CSV результата:

```
field, class, value
predicted_class: Менингиома,
confidence: 0.983
class_probability: Менингиома - 0.983
class_probability: Глиома - 0.017
...
segmentation_output: output.png
```

### 5.4. Запуск

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

Зависимости зафиксированы версиями в `requirements.txt`
(flask 3.1.3, torch 2.14.1, torchvision 0.29.1, monai 1.6.1,
segmentation-models-pytorch 0.5.0, pillow 12.3.0, numpy 2.5.3).

## 6. Практическое применение

### 6.1. Место в процессе работы медицинской организации

- врач (или медрегистратор при оцифровке архива) загружает снимок
  исследования;
- программа за ~1 секунду возвращает предположительный класс, уверенность
  и предполагаемую область опухоли;
- врач использует результат для повышения скорости обработки и упрощения анализа снимка — финальное заключение остаётся за специалистом.

Формат не требует интеграции с PACS на этапе прототипа (загрузка файла),
но архитектура допускает подключение DICOM-источника: предобработка уже
работает с произвольным разрешением и контрастом.


### 6.2. Ресурсы

| Параметр | Значение |
|---|---|
| CPU | обычный офисный (4 ядра), GPU не требуется |
| Оперативная память | ~1.5 ГБ (6 моделей в памяти) |
| Диск | ~1 ГБ (код, веса, пробная выборка) |
| Время инференса | ~1 с на снимок (CPU) |
| Развёртывание | локальный сервер / внутренний контур клиники |

Решение работает на CPU — специально для эксплуатации без GPU-инфраструктуры,
что типично для региональных больниц. При наличии GPU используется
автоматически (PyTorch CUDA).

### 6.3. Защита медицинской информации

Реализованные в прототипе меры:

- **локальная обработка**: все вычисления и хранение — на сервере внутри
  контура организации, внешние сервисы не задействованы;
- **минимизация данных**: загруженный оригинал сохраняется под случайным
  UUID (имя файла пользователя не используется и не хранится), удаляется
  сразу после обработки; в результатах остаются только производные файлы
  (превью, снимок с маской, CSV с числами) под тем же UUID;
- **ограничение размера** (10 МБ) и строгая валидация формата загружаемых
  файлов;
- результаты предыдущих обработок разделены случайными идентификаторами
  и не связаны с персональными данными.

Варианты дополнительных мер (выходят за рамки прототипа): HTTPS/TLS внутри контура,
разграничение доступа по ролям (врач/администратор), журналирование доступа,
хранение в аттестованном сегменте в соответствии с требованиями ПП РФ № 1119,
обезличивание по приказу Роскомнадзора № 140 при использовании данных
для дообучения.
